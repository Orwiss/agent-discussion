우리 프롬프트, 논문에 실릴 수준인가?

멀티에이전트 LLM 논문들의 프롬프트 보고 관행(근거·공개범위·형식)과 대조 · 2026-07-01

판정. 근거(grounding)는 오히려 상위권(우리는 프롬프트를 이론에 명시적으로 인용 — 대부분 논문은 "역할을 이렇게 줬다" 서술뿐). 공개 가능성도 높음(전부 코드에 있어 100% 공개 가능). 하지만 "지금 이 상태 그대로"는 아직 논문 수준이 아니다 — 세 가지 갭 때문: ① 숨은 후처리 파이프라인 미공개(guardrails·재시도·요약기가 산출물을 실제로 변형), ② 부록 미정리 + 한국어, ③ 프롬프트 조립 복잡도(페르소나+공통규칙+조건블록+런타임+phase가 조립·조건분기). 이 셋을 메우면 평균 이상이 된다.

1. 멀티에이전트 논문은 프롬프트를 어떻게 싣나 (관행)

공개 범위 — 신흥 표준 = "전체 프롬프트를 부록 또는 공개 레포"

  • Generative Agents (Park et al., UIST 2023): 부록에 프롬프트 템플릿 전문 + GitHub 레포(joonspk-research/generative_agents). HCI(UIST)에서 사실상 기준선.
  • MetaGPT (Hong et al., ICLR 2024): 역할별 프롬프트 prefix + 레포 공개.
  • PartnerMAS·STAC·TASTE 등 최근 arXiv: 부록(App G / App A·B / App D)에 재현에 필요한 전체 프롬프트를 그대로 첨부.
  • 단, 감사 논문(아래)은 "실제로 전체 프롬프트를 공개하는 논문은 드물다"고 지적 → 제대로 공개하면 그 자체로 상위권.

근거(grounding) — 프레임워크마다 다르고, 대개 "이론 인용"은 약함

  • MetaGPT: 인간 협업의 표준작업절차(SOP)를 프롬프트 시퀀스로 인코딩 — "워크플로를 근거로"
  • Generative Agents: believable behavior(사회과학적 그럴듯함)를 근거로 페르소나 설계
  • CAMEL: role-playing / inception prompting — 역할 배정 자체가 근거
  • → 대부분 "이런 역할을 줬다"는 서술 수준. 협업 이론을 직접 인용해 프롬프트를 정당화하는 논문은 드물다.

공개도 체크리스트 (감사 논문의 rubric)

"What Twelve LLM Agent Benchmark Papers Disclose About Themselves" (arXiv 2605.21404) — 에이전트 논문이 공개해야 할 항목을 점수화.

범주공개해야 할 것

3. 우리 vs 관행 — 핵심 차이

차원관행(멀티에이전트 논문)우리
근거대개 "역할을 이렇게 줬다" 서술. 이론 인용 드묾.더 강함 — 협업 이론을 직접 인용. 논문의 "Prompt design rationale" 절로 쓰기 좋음.
공개전체 프롬프트를 부록/레포에(단 실제론 드묾).가능하나 아직 안 함 — 부록화+번역 남음.
후처리 공개rubric이 요구하나 많은 논문이 부실.현재 미공개 — 우리는 후처리가 많고 산출물을 바꿈 → 안 밝히면 재현성·타당성 공격 표적.
조작(manipulation) 노출조작을 verbatim으로 보여줘야 신뢰됨.이미 초안 있음 — prompt_comparison.html이 사실상 조작 공개 부록의 초안.

4. 논문 수준으로 만들기 — 체크리스트

  • 전체 프롬프트 부록 표 — 조건(Cen/Dec) × 역할(PM/D/E) × phase, 한국어 원문 + 영어 번역 병기.
  • 조립 구조 다이어그램 — 페르소나+공통규칙+주제+조건블록 → phase prefix → (Cen)런타임 트리거.
  • 후처리 파이프라인 명시 — guardrails(제거·치환·중복차단), truncation 재시도, 요약기 에이전트, blank-line collapse를 "산출물에 적용한 자동 처리"로 보고. 최우선
  • Model/Config 표 — 모델명·버전·temperature·max token·seed·반복 횟수(web.py/config에서 추출).
  • Orchestration 보고 — 라운드 수·speaker selection·user turn 간격·종료 조건.
  • Prompt design rationale 절 — 이미 근거 보유(이게 우리 강점). 이론→프롬프트 매핑을 명시.
  • 조작 노출 부록 — prompt_comparison.html의 "조건별 블록 verbatim"을 논문 부록으로.

5. 한 줄 결론

근거와 공개-가능성은 이미 논문 상위권 잠재력. 실제로 실릴 수준이 되려면 남은 건 "쓰기 작업" 성격 — 부록화·번역·조립도·후처리 명시. 이 중 후처리 파이프라인 공개가 가장 시급하다(산출물을 바꾸는데 안 밝히면 재현성 공격의 정확한 표적). 나머지는 이미 가진 재료를 정리하는 일이다.

근거: 웹검색으로 확인한 논문 관행(Park 2023 UIST 부록+레포, MetaGPT SOP, CAMEL role-play, PartnerMAS/STAC/TASTE 부록 공개) + 감사 논문 rubric(arXiv 2605.21404, 본문 fetch). 우리 측 사실은 읽은 코드(simple_agents.py·common.py·centralized.py·guardrails.py) 기준. Model/temp/seed는 미확인 — 별도 확인 필요.
